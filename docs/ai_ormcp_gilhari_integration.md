# Phase 5 — ORMCP / AI Agent Integration

_Last updated: 2026-06-13 11:38 PDT_

**Goal:** Connect your running Gilhari microservice to an AI agent so it can query and interact with your business data through natural language.

Once your microservice is up and passing a health check, this step takes just a few minutes. Phase 3 generates a tailored **`connectORMCP.md`** file in your project directory with all the values for your specific project already filled in.

---

## What is ORMCP?

[ORMCP](https://github.com/SoftwareTree/ormcp-docs) (ORM Model Context Protocol) is an MCP server that bridges AI language models to your database through Gilhari microservice using the [Model Context Protocol](https://modelcontextprotocol.io/) standard.

Instead of exposing raw SQL or generic REST calls, ORMCP gives the AI agent a curated, object-oriented view of your business data. The agent reasons about `Employee`, `Order`, or `Product` objects — not table rows. This approach:

- **Improves reasoning clarity** — the agent sees meaningful domain objects, not raw relational structure
- **Reduces token usage** — shaped, scoped JSON objects rather than verbose SQL result sets
- **Establishes a governance boundary** — the agent can only see and operate on what your `.jdx` ORM spec exposes; sensitive columns you removed in Phase 2 stay invisible
- **Supports read-only mode** — set `READONLY_MODE=True` to give the agent query-only access

The `model_overview` you provided during Phase 1 is embedded in the ORM spec and read by ORMCP at startup, giving the AI agent immediate semantic context about your domain.

## Step 1 — Install ORMCP Server

**Production (after beta):**
```bat
pip install ormcp-server
```

> **macOS note — virtual environment location:** If you install ORMCP inside a virtual environment, do not create the venv inside `~/Desktop/` or `~/Documents/`. macOS restricts access to these folders for apps without Full Disk Access, and Claude Desktop will throw a `PermissionError` when trying to read `pyvenv.cfg`. Create the venv in an unrestricted location instead, for example:
> ```bash
> python3 -m venv ~/.ormcp-venv
> source ~/.ormcp-venv/bin/activate
> pip install ormcp-server
> ```
> Then point Claude Desktop's `"command"` to `~/.ormcp-venv/bin/ormcp-server`.

**Beta users:** Request access at [softwaretree.com/products/ormcp](https://www.softwaretree.com/v1/products/ormcp/ormcp-introduction.php) to receive your token, then:
```bat
pip install --index-url https://YOUR_TOKEN@pypi.fury.io/softwaretree/ ^
  --extra-index-url https://pypi.org/simple ormcp-server
```

## Step 2 — Verify your microservice is running

```bat
curl -s http://localhost:80/gilhari/v1/health/check | python -m json.tool
```

ORMCP connects to Gilhari at startup. Start Gilhari manually first (recommended) using the generated `run_docker_app.cmd` / `./run_docker_app.sh`.

## Step 3 — Configure your AI client

**Your project's `connectORMCP.md`** (generated by Phase 3) contains the exact configuration snippet with your image name, port, and service name already filled in. Open it and copy the snippet directly into your AI client config.

### Claude Desktop (general form)

Add to `claude_desktop_config.json`:

**Windows:** `%APPDATA%\Claude\claude_desktop_config.json`
**macOS:** `~/Library/Application Support/Claude/claude_desktop_config.json`

```json
{
  "mcpServers": {
    "my-service-ormcp": {
      "command": "ormcp-server",
      "args": [],
      "env": {
        "GILHARI_BASE_URL": "http://localhost:80/gilhari/v1/",
        "MCP_SERVER_NAME": "my-service-ormcp",
        "GILHARI_NAME": "my-service",
        "GILHARI_IMAGE": "my-service:1.0",
        "GILHARI_PORT": "80",
        "READONLY_MODE": "True"
      }
    }
  }
}
```

Claude Desktop starts the ORMCP server automatically — no separate terminal needed.

### Other MCP clients

ORMCP works with any MCP-compatible client including Gemini CLI, OpenAI GPTs (in developer mode), and custom agents. See the [ORMCP documentation](https://github.com/SoftwareTree/ormcp-docs) for client-specific configuration.

## Environment variables reference

| Variable | Description | Default |
|---|---|---|
| `GILHARI_BASE_URL` | URL of your running Gilhari microservice | `http://localhost:80/gilhari/v1/` |
| `MCP_SERVER_NAME` | Identifier shown in logs and AI client tool lists | `ORMCPServerDemo` |
| `GILHARI_NAME` | Container name (used for auto-start) | — |
| `GILHARI_IMAGE` | Docker image for auto-start | — |
| `GILHARI_PORT` | Port for auto-start | — |
| `READONLY_MODE` | Set `False` to allow write operations (create, update, delete). Defaults to `True` — read-only is the safe default for AI agents. | `True` |
| `GILHARI_TIMEOUT` | API timeout in seconds | `30` |
| `LOG_LEVEL` | Logging verbosity: `DEBUG`, `INFO`, `WARNING`, `ERROR` | `INFO` |

## ORMCP HTTP mode

By default, ORMCP runs as a local process started by your AI client. It also supports an **HTTP server mode** that makes it accessible from other machines, mobile devices, or any HTTP-capable client:

```bash
ormcp-server --http --port 8080
```

HTTP mode is more versatile than the default local process mode:
- Accessible from any machine on the network, not just localhost
- Works with mobile apps, web applications, and custom clients
- No local ORMCP installation needed on client machines
- Suitable for team or shared deployments

See the [ORMCP documentation](https://github.com/SoftwareTree/ormcp-docs) for HTTP mode configuration details.
